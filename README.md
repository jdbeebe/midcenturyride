# Mid-Century Ride

A flipbook-style guide to the mid-century modern houses of New Canaan, CT, visited on a ride hosted by Bill Adamsen and the Ridgefield Bicycle Club.

## What's here

- `index.html`: chooser for the three design directions
- `directions/a-monograph/`: **A · The Monograph**. A cream-paper architecture book, two-page spreads on desktop.
- `directions/b-cue-deck/`: **B · The Cue Deck**. Handlebar cue cards that flip up from a top hinge.
- `directions/c-after-dark/`: **C · After Dark**. Dark, cinematic, photo-led pages.
- `shared/flipbook.js` + `flipbook.css`: the page-turn engine (drag, flick, tap, keys; 3D leaves with lighting).
- `shared/common.js`: photo lookup, drawn fallback houses, and the bicycle mark.
- `data/homes.js`: the 26 houses from the ride's Google Sheet.
- `data/route.js`: the Ride with GPS route (generated by `scripts/build-route.py`).
- `assets/img/`: photos, `credits.json` (source and license per photo), and the generated `manifest.js`.

## Run it

Everything is static, so you can open `index.html` directly. To test on a phone, serve the folder:

```bash
python3 -m http.server 4173
```

## Photos

Add or replace a photo by dropping it into `assets/img/` and adding an entry to `credits.json`. Then run:

```bash
python3 scripts/build-manifest.py
```

Houses without a photo show a line drawing instead.

## Route

Mileage, stops, maps and turn-by-turn directions come from the Ride with GPS route
https://ridewithgps.com/routes/54307217. Where the route marks a house Stop or Ride by, that overrides the sheet.
After the route changes, refresh the data with:

```bash
python3 scripts/build-route.py
```

Each house is linkable: add `#house-12` (any house number) to a direction's URL.

## Standalone book (Version A)

`book/` is Version A on its own: one `index.html` with everything inlined, plus its photos, and no links
to the other directions. It's generated from `directions/a-monograph/`, so edit A there and rebuild:

```bash
python3 scripts/build-standalone.py
```

The `book/` folder can be copied to any static host as-is.

## Recap and "ride it again?" vote

`recap/` is the post-ride recap. Its vote is handled by `server.js`, a dependency-free Node server that
serves the whole site and stores votes in `votes.json`. On Railway it writes to the attached volume
(`RAILWAY_VOLUME_MOUNT_PATH`); locally it writes to `data-local/`. Run it with `npm start`.

- `GET /api/votes` returns the tally.
- `GET /api/health` reports whether votes persist on the volume (`storage: "volume"`).
- `POST /api/vote` with `{ voter, choice: "yes" | "maybe" | "no" }` records one vote per browser, which can be changed.

On GitHub Pages (static only) the recap page links to the Railway copy to vote.
